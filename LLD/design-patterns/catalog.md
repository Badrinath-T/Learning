# Design Patterns: Catalog

## Creational

| Pattern | Purpose |
|---|---|
| Factory Method | Delegate object creation to subclasses |
| Abstract Factory | Create families of related objects |
| Builder | Construct complex objects step by step |
| Singleton | Ensure only one instance exists |

## Structural

| Pattern | Purpose |
|---|---|
| Adapter | Convert one interface to another |
| Decorator | Add responsibilities by wrapping an object |
| Composite | Treat individual objects and groups uniformly |
| Facade | Provide a simplified interface to a subsystem |
| Proxy | Stand in for another object |
| Bridge | Separate abstraction from implementation |
| Flyweight | Share objects to save memory |

## Behavioral

| Pattern | Purpose |
|---|---|
| Strategy | Choose an algorithm at runtime |
| Observer | Notify multiple listeners of changes |
| Command | Encapsulate requests as objects |
| State | Change behavior based on current state |
| Iterator | Traverse collections |
| Mediator | Coordinate communication between objects |
| Chain of Responsibility | Pass requests through handlers |
| Template Method | Define an algorithm skeleton |
| Visitor | Add operations without changing classes |
| Memento | Save and restore object state |
